# One Print Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bambuddy's print log becomes the record of every print: print-lab links its runs to it by name and keeps a
small evidence snapshot, Pi Hub reads it instead of its own `prints` table, and Local AI shows the result.

**Architecture:** Three repos, three parts, each shippable alone. print-lab (Python, uv) links in its existing 60 s
`lab pull` and adds fields to `page.json`. Pi Hub (FastAPI) gets `bambuddy.prints()` and points every former table
reader at it. Local AI (Node, plain browser scripts) renders the new `page.json` fields.

**Tech Stack:** Python 3 + pytest (print-lab, Pi Hub), Node test runner (Local AI, Pi Hub JS), Bambuddy 1.2.5.7 REST.

**Spec:** `/Users/billrahe/dev/pi-hub/docs/superpowers/specs/2026-10-27-one-print-design.md`

## Global Constraints

- Lab name pattern (P2), used verbatim in print-lab and Pi Hub:
  `^(?P<project>[a-z0-9-]+)_(?P<exp>E-\d{3,})_(?P<build>BLD-\d{3,}-\d{2,})$`
- Status words (P5): `completed` → Finished, `failed` → Failed, `cancelled` → Cancelled, `printing` → Printing. Any
  other Bambuddy status shows as its own word capitalised.
- Print-log endpoint: `GET /api/v1/print-log/` with `X-API-Key`; response `{"items": [...], "total": n}`; item fields
  used: `id`, `archive_id`, `print_name`, `status`, `started_at`, `completed_at`, `duration_seconds`,
  `filament_used_grams`, `cost`, `failure_reason`. Archive endpoint: `GET /api/v1/archives/{id}` (`print_time_seconds`).
- Bambuddy timestamps are naive ISO strings in **UTC** (entry 26: `started_at` 20:36 for a 16:36 EDT print). Parse
  them as UTC everywhere.
- Never write to Bambuddy. print-lab never blocks on the network (timeouts ≤ 5 s; failures mean "try next pull").
- Bambuddy links point at `https://bambuddy.home.arpa/` (never an IP).
- print-lab has another session's uncommitted files (`projects/hex-tile/sources/sources.json`, `.DS_Store`): never
  stage or modify them; never touch v73/v74 sources.
- Local AI: work in a worktree from `origin/main` (the main checkout is 68 behind with a local `app/server.js` change);
  never push `main` or `release`; stop before opening a PR.
- Pi Hub deploys are the owner's (`git push pi main`); stop before it.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. A print-log entry still `printing` when first pulled → linked now, snapshot written once when it ends (Task 2 test).
2. Bambuddy answers with an error or garbage JSON → `lab pull` carries on with its other work and the last-seen id is
   not advanced (Task 3 test).
3. A naive UTC timestamp near midnight → the hub's "this week" and the lab's `started_at` agree with Bambuddy
   (Tasks 1 and 5 tests).
4. The owner already recorded `lab exp usage` before the print ended → their minutes/grams/failure point stay; the
   Bambuddy values sit beside them (Task 2 test).
5. A lab-named print for an experiment that doesn't exist (renamed, typo) → "outside the lab", never an exception
   (Tasks 2 and 5 tests).
