## 2. Request payloads: LA posts vs PH `request_problem`

PH validators mirror LA's server (`actProblem` / `photosProblem` / `obsProblem`). The gaps are in what **PH's page** sends compared with what LA's page sends, and where the PH route behaves differently.

| Kind | LA page posts | PH route accepts | Difference to handle |
|---|---|---|---|
| verdict | `{id,kind,experiment,run,payload{grades,lighting,note,inconclusive,replace}}`; `–` grades become `null`; lighting is required (null if unset) | `request_problem` returns None for verdict: no payload shape check. `run` must match `RUN_ID_RE`, so `run:null` gives 400 "Invalid run id". The whole request is capped at 4 KB. | PH page defaults lighting to "diagnostic" (LA makes you choose) and has no "–". Align with LA. The Mac validates the grades. Experiments with no run cannot take a verdict (same in LA's UI, which only offers it when printing). |
| photos | `payload{run, photos:[{sha256,tab}]}`; PUT `/incoming/<sha>.jpg` first | 1-50 photos, `SHA_RE`, tab `^[A-Za-z0-9_.-]{1,16}$` or null | Same. The `run` is required by the route. |
| start | `experiment` (E-n), `payload{tapped_at: ISO}`, top-level `run_seen: run\|null` | `tapped_at` must parse as a date and be under 40 chars. `run` is forced to None. `run_seen`, if present, must be a string matching the run-id regex (a null `run_seen` is accepted and skipped). | A page with `x.run` null sends `run_seen:null`, which is fine. Send `new Date().toISOString()`. |
| approve | `payload{reason, build_seen, reasons_seen[]}`, reason trimmed | reason 1-500 after strip, `build_seen` matches `^[A-Z]{1,4}-\d{1,6}-\d{1,4}$`, `reasons_seen` is a list of up to 30 guard codes `^[a-z][a-z0-9_]{0,39}$` | `build_seen` is the last build id from the record. Codes come from `guards[].code`. Wrong shapes give 400 with a plain sentence. |
| abandon | `payload{reason}` | reason 1-500 | Same. |
| observation | `run: exp.run`, `payload{snapshots[1-8]}`; each snapshot `{subject,viewing,outcomes,source}` | same, 16 KB cap, each snapshot needs dict `subject`, `outcomes`, `source` | `run` required (`RUN_ID_RE`). A pending observation needs the draft kept. |
| observation_correction | LA page never sends it | `payload{observation: OBS-0001, expected_rev:int, snapshot, reason}` | Out of scope. |

General differences to code for:
- Error text key: LA's server returns `{error}`. PH returns FastAPI `{detail}` (400/401/403/404/413/429). Pages must read `detail` (PH l.506 does; the `core.js` `api()` helper reads `detail || error`).
- Status values: `pending`, `applied`, `refused`, and `conflict` (observation). PH's `renderRequestsList` treats everything other than applied/refused as warn, which is fine.
- `GET /requests` items have `{id,kind,experiment,status,message,at}` in both (no payload). A pending item that is older than 120 s should say "The Mac hasn't picked this up" (LA `actText` l.459).
- 429 when 20 are pending: the message is already user-readable, so show it.
- Request id: `rq-` plus 16 hex, same in both (`makeRequestId`).

## 3. Pi Hub specifics a port must respect

- **Escaping.** `esc()` at lab.js:7 escapes `& < > " '` and returns `""` for null. Every dynamic value goes through it, including attribute values and values interpolated into `style`. `h()` from core.js sets text, not HTML. Do not put raw values in a selector either (LA uses `CSS.escape`). Colour values must pass `^#[0-9a-fA-F]{6}$`. Photo URLs use only `p.sha256` that match `^[0-9a-f]{64}$` (LA checks this in photos.js l.9; PH l.106 does not). Export `esc` and the pure renderers (`runLines`, `outsideHtml`, `spoolColour`) so node can test them. `lab.js` imports `core.js`, and `test_settle.mjs` shows `core.js` imports fine under node.
- **Sign-in.** `/api/lab/*` needs `need(request,"household")`. No cookie gives **401** "Enter the household PIN first."; a kid gives **403**. `core.js` has `whoami()` and `ensure("household")`, which shows the PIN sheet (`pinSheet`, POST `/api/signin`) and returns true or false. Today lab.js never calls `ensure`: a 401 on `load` bubbles through `api()` as a thrown Error to main.js's generic "Couldn't load print lab" notice. A 401 on a POST/PUT just prints `detail` in the sheet. The spec wants a sign-in prompt: on a 401 (load or action), call `ensure("household")`, then retry the action once (GET `load` again, or the send). On 403 show the kid message and nothing else. Avoid prompting from the 15 s refresh loop. Call `ensure` once per failure, and pass on the error otherwise.
- **Polling and backoff.** There are two loops. (a) main.js `setInterval(refresh, every*1000)` with `every = 15` (main.js:258). There is no backoff; failures show the page notice and the loop continues. `loading` blocks overlap, and `LOAD_DEADLINE_MS` is 45 s. (b) lab.js `pollVerdictResult`: `setInterval(check, 500)` with no backoff, swallowing every error and a non-OK response silently, the "hasn't picked this up" text after 120 s but no stop. `leave()` clears it. A port should replace that with a `setTimeout` chain (1 s, then x1.5 to a 10 s cap, reset on change, stop on applied/refused or after about 10 min), pause while `document.hidden`, and share one poll for verdict/photos/act/observation requests (LA has three separate loops: 500 ms, 1000 ms, 1500 ms). Clear the timer in `leave()`. Do not read `every` as a poll: an export can set `every = 3` if the fingerprint check is cheap, but keep `load` itself at 15 s or longer.
- **Same-origin guard.** `app.py:guard` rejects any POST/PUT whose `Origin` (or `Referer`) host differs from `Host` with 403 "This change has to come from the hub's own page." Use relative `fetch("/api/lab/...")` only. Do not set an `Origin` header and do not call another host from the page (the `X-Hub-Mac-Key` bypass is for the Mac only). Bambuddy and photo links are plain `<a>` and `<img>` GETs, so they are fine. Bodies: 64 KB cap on request JSON (4 KB, or 16 KB for observations, checked on compact JSON) and 8 MB on photos.
- **Service worker.** `hub/static/sw.js:2` `SHELL = "pi-hub-shell-v101"`. Any change to lab.js or lab.css, or a new JS file, needs a bump to v102 (or higher), and every new static file added to the `FILES` list (lab.js and lab.css are in it; new files such as `lab-photos.js` must be added). `tests/test_appliance_ui.py:65` asserts the exact string `pi-hub-shell-v101`, so update it in the same commit. Check that nothing else pins the version.
- **Tests.** No test imports `lab.js` today (grep finds none). Backend tests: `tests/test_lab.py` (sync, records, photos), `test_lab_requests.py` (kinds and caps), `test_lab_access.py` (401/403, Mac key), `test_lab_limits.py`, `test_lab_disk.py`, `test_deploy_lab_key.py`. Run `HUB_NO_SAMPLER=1 .venv/bin/python -m pytest -q -p no:cacheprovider tests` and `node --test tests/*.mjs` (README.md:34-35). Add `tests/test_lab_page.mjs` with a fixture index modelled on `build_index` output. Playwright (`tests/browser/structure.mjs`) is manual from the Mac, not a release gate.
- **Page conventions.** `mount(state)` and `load(state)` get `state.root` and `state.context`. Sheets are `<dialog>` elements outside `state.box`, so re-rendering the body does not close them. Buttons use `btn-outline` and `primary` (LA uses `btn-primary`, `btn-danger`, `banner`). `lab.css` has none of the LA classes `lab-print`, `lab-outside`, `lab-swatch`, `lab-thumb*`, `lab-live`, `lab-jump`, `lab-wipe`, `lab-changed`, `lab-ai`, `lab-plans`, `lab-defects`, `lab-conflict`, `lab-compare`, `lab-viewer`. Port them from `app.css` (blocks near l.2300, 2731 and 3059; `grep -n "lab-"`) and restyle with the hub's `tokens.css`. There is an amber-colour check in `test_appliance_ui.py`, so do not copy hard-coded amber values.
